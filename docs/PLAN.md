# 盈亏透镜 ProfitLens · 项目规划

> 本文件是项目的总体规划与设计依据。功能迭代时同步更新，变更记录见 [CHANGELOG](../CHANGELOG.md)。

## 1. 要解决的问题

网点管理员从「网点发件盈亏分析」系统导出某个客户的**单号明细**后，需要快速回答：

1. 这个客户的**报价是怎么定的**？系统里的收入和我们给客户的报价是否一致？
2. **哪些流向、哪些重量段**在赚钱，哪些在亏钱？亏多少？
3. 客户的**重量段和流向结构**是什么样的（占比）？
4. 扣除网点自己的**线下操作和管理成本**后，真实的**纯利润**是多少？
5. 如果**调整报价**，利润会怎么变？给新客户怎么报价才合理？

## 2. 设计原则

| 原则 | 落地方式 |
| --- | --- |
| 最简单有效 | 一个网页文件，双击即用；无需安装 Python、数据库或 Office 插件 |
| 数据不出本机 | 所有解析与计算都在浏览器本地完成，不上传任何服务器 |
| 百万行级性能 | Web Worker 流式解压 + 逐字节解析 XLSX；列式 TypedArray 存储；聚合在毫秒级 |
| Windows / Mac 通用 | 只依赖现代浏览器（Chrome / Edge / Safari / Firefox） |
| 易分享 | ① GitHub Pages 在线地址；② 单文件离线版 `ProfitLens.html`，可微信/U 盘分享 |
| 口径透明 | 每个关键指标带「ⓘ 角标」，悬停显示计算公式和数据来源 |
| 可持续迭代 | TypeScript + 单元测试 + CI + 语义化版本 + CHANGELOG |

## 3. 样本数据扫描结论（2026-10-11）

对两份真实导出（约 5 万单与 38 万单，客户信息与价格不入库）做了全面扫描：

- 字段 26 列：揽收日期、运单号、结算对象、面单账号、目的地（省）、结算重量、签收状态、退件、自发自签、是否已发货，以及收入/成本/利润三级拆分。
- 勾稽关系 100% 成立：`收入 = 中转收入 + 面单收入 + 增值收入`；`成本 = 中转 + 派费 + 面单 + 增值 + 政策`；`利润 = 收入 − 成本`。
- **增值收入 = 增值成本**（退件费等代收代付），对利润无影响。
- **政策费用多为负数**（补贴）。
- 重量为 2 位小数；少量单重量为 0 且收入为 0（异常单）。
- 导出文件使用 inlineStr（字符串内联），每行约 1.4KB XML。38 万行的文件解压后 548MB，百万行约 1.4GB —— 必须流式解析。
- 其中一位客户在月中调过价（面单费下调），同一份导出跨两个价格时段 → 需要**调价识别**。

### 3.1 报价结构规律

单票运费 = 面单收入（固定面单费）+ 中转收入（按分区 × 重量段加价）。重量段「左开右闭」，典型分界 1.2 / 1.5 / 2 / 3kg，3kg 以上按「基价 + 单价 × ⌈重量 − 3⌉」续重。省份按价格自然聚成 4–8 个分区：一般省份、江浙皖、闽粤、京沪、偏远五省（甘蒙琼宁青）、新藏（首重 1kg + 按实重续重）。

两份样本的还原覆盖率均为 **100%**（剩余个位数例外单正是核对要找的对象）。示例数据 `src/engine/demo.ts` 按同样的结构虚构了一套价格。

## 5. 技术架构

```
┌──────────── 浏览器（全部本地） ────────────┐
│  UI 层  React + ECharts                      │
│   ├─ 总览 / 报价 / 利润矩阵 / 结构 / 数据 / 帮助 │
│   └─ 导出：modern-screenshot（PNG）+ jsPDF   │
│  计算层  src/engine（纯函数，可单测）         │
│   ├─ dataset    列式存储：Float64Array + 字典编码 │
│   ├─ aggregate  掩码筛选 + 整数键分组聚合      │
│   ├─ quote      报价推断 / 定价 / 核对 / 模拟  │
│   └─ metrics    指标注册表（口径 + 角标说明）   │
│  解析层  Web Worker                           │
│   ├─ zip       原生 DecompressionStream 流式解压（fflate 兜底）│
│   ├─ xlsx      逐字节 SAX 解析 sheet XML（inlineStr / sharedStrings）│
│   └─ csv       UTF-8 / GB18030 自动识别        │
└──────────────────────────────────────────────┘
构建：Vite → 单文件 HTML（worker 内联）
发布：GitHub Actions → Pages（在线版）+ Release（离线单文件）
```

### 5.1 性能预算

| 环节 | 100 万行目标 |
| --- | --- |
| 解压 + 解析 | ≤ 15 秒（实测 115 万行 3.2 秒） |
| 内存 | ≤ 300MB（列式存储，不保留整行字符串） |
| 切换筛选/图表 | ≤ 200 毫秒 |

### 5.2 报价推断算法

1. **价格口径**：默认 `面单收入 + 中转收入`（客户实际支付的运费，不含增值费）。
2. **断点识别**：每个省份按重量排序，取每个重量的众数价格，相邻价格变化处即候选断点；跨省份投票，取被多数省份支持的断点，并在区间内取「整齐」数值（0.5 > 0.1 > 0.05 > 0.01 的倍数）。
3. **分段定价**：每省 × 每段取众数价格与覆盖率。
4. **续重拟合**：对超出固定段或段内价格不一致的样本，尝试 `基价 + 单价 × g(w − 起点)`，g ∈ {向上取整, 按实重, 向上取整到 0.5kg}，选覆盖率最高者。
5. **分区聚类**：段价格完全相同的省份归为一个分区；续重公式在分区内合并样本拟合。
6. **核对**：逐单计算「应收」与「实收」差额，容差 0.005 元。

## 6. 版本与协作

- 语义化版本：`主版本.次版本.修订号`，每次发布打 tag，Release 附离线单文件。
- 分支：`main` 永远可用；功能在 `feat/*` 分支开发后合并。
- CI：每次推送运行类型检查、单元测试、构建。
- 真实客户数据**禁止入库**（`.gitignore` 已屏蔽 `local-data/`、`*.xlsx`）；仓库只含脱敏的合成示例数据生成器。

## 7. 需要用户进一步提供的资料

1. 正式报价单（Excel 截图或文件）一份，用于校准报价模板格式。
2. 更多客户的导出数据（尤其是：分层报价/汇总计费客户、含城市字段的导出、有退件/到付/保价等增值业务的客户）。
3. 网点线下操作与管理成本的大致口径（按票、按月固定、按重量？）。
4. 是否需要按「城市」甚至「区县」分析流向。
